# Cloud Workspace

A clean, Linear-style workspace for small teams. Conversations, calls, files, and documents live in one place. The UI is light-only and follows Notion and Linear conventions.

## Stack

- Next.js 16 (App Router, React Server Components)
- Bun (package manager and scripts)
- TypeScript
- Drizzle ORM + libsql (SQLite)
- Better Auth (GitHub and Google sign-in)
- Tailwind CSS v4 + shadcn/ui (Radix)
- lucide-react icons
- Inter and Geist Mono via `next/font`

## Current UI

The workspace shell lives in `components/workspace-shell.tsx`. Views switch with local state:

- Home: recent files, live meeting, upcoming events
- Inbox: mentions and notifications
- Messages: channels and chat
- Files: shared documents, images, spreadsheets; list and grid views
- Calls: live room and call history
- People: team directory

Also included:

- Workspace sidebar with Recents, Favorites, and Private groups
- Search dialog with quick access
- Create menu (document, upload, call)
- Profile menu
- Mobile drawer navigation
- Toast feedback for actions

Auth is wired: `app/page.tsx` reads the Better Auth session and passes the user name into the shell. The rest of the workspace is frontend-only for now. Group chat persistence, real file uploads, storage, and video calls are planned.

## Getting Started

1. Install dependencies:

```bash
bun install
```

2. Create the environment file:

```bash
cp .env.example .env
```

3. Fill in `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, and the OAuth pairs in `.env`:

```bash
GITHUB_CLIENT_ID=...
GITHUB_CLIENT_SECRET=...
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
```

Empty OAuth credentials log a warning at build time, but the build succeeds.

4. Push the schema and run the dev server:

```bash
bun run db:push
bun run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Database

- Local development uses SQLite at `db/../sqlite.db` or via `DATABASE_URL="file:..."`.
- Production uses Turso. Set `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`; these win over `DATABASE_URL`. Create a database with:

```bash
turso db create cloud-workspace
turso db show cloud-workspace --url
turso db tokens create cloud-workspace
```

- Set `TURSO_DATABASE_URL` to the URL shown by `turso db show` and `TURSO_AUTH_TOKEN` to the token from `turso db tokens create`. Add both to Vercel.
- Run migrations against the target database: `bun run db:migrate` (local `DATABASE_URL`) or `TURSO_DATABASE_URL=... TURSO_AUTH_TOKEN=... bun run db:migrate`.
- Health endpoint: `GET /api/health` returns `200` with `{"status":"ok","database":"ok"}` when the database answers a query, or `503` otherwise.

## Scripts

| Command | What it does |
| --- | --- |
| `bun run dev` | Start the dev server |
| `bun run build` | Production build |
| `bun run start` | Run the production build |
| `bun run lint` | Biome check (no ESLint) |
| `bun run format` | Biome format |
| `bun run db:generate` | Schema to `drizzle/` SQL |
| `bun run db:migrate` | Apply migrations |
| `bun run db:push` | Push schema without migration files |
| `bun run db:studio` | Open the database GUI |

## Structure

```
app/
  layout.tsx          Root layout, fonts, metadata
  page.tsx            Home; reads the session, renders the workspace
components/
  workspace-shell.tsx The workspace UI (client component)
  ui/                 shadcn primitives
  auth-buttons.tsx    Sign-in and sign-out
db/
  index.ts            libsql client
  schema.ts           Generated by Better Auth CLI
lib/
  auth.ts             Better Auth config
  auth-client.ts      Better Auth client
drizzle/              SQL migrations
```

Key conventions:

- No `src/` directory. Code lives in `app/`, `components/`, `lib/`, and `db/`.
- Path alias `@/*` maps to the repo root.
- `db/schema.ts` is generated from `lib/auth.ts`. Do not edit it by hand.
- The UI is light-only. Linear-style color tokens live in `app/globals.css` (`--bg-sidebar-color`, `--bg-base-color`, and friends).
- Use `bun` for all package operations.
